# Документация «ТАРАН-ЭКСПРЕСС» 3.2

Проектная документация к учебной кликер-аркаде на Python/Pygame.

| Параметр | Значение |
|---|---|
| Проект | «ТАРАН-ЭКСПРЕСС» (Taran Express) |
| Версия игры | 3.2 |
| Автор | Серик Жанторе Батырханулы |
| Группа | 3-26п |
| Дата комплекта | 19 ноября 2026 |
| Состав | 21 документ DOCX + 1 книга XLSX + папка `09_Исходный_код` |
| Материалы | 8 схем PNG + 8 файлов `.drawio`, 11 скриншотов, график производительности |
| Исходный код | 40 файлов: 7 656 строк в 17 модулях игры, мобильная сборка, 3 набора проверок |
| Размер папки | около 10,3 МБ |

Комплект описывает фактическое состояние кода версии 3.2: числа, имена
модулей, механики и результаты проверок взяты из проекта, а не написаны
«по памяти». Незакрытые вопросы (BR-12, проверка на устройствах, юзабилити)
указаны прямо в документах.

## Исходный код

В папке `09_Исходный_код` лежит тот самый код, по которому собран
комплект: `game.py`, `progression.py`, `prog_ui.py`, пакет `taran/`
(14 модулей), мобильная сборка `mobile/` (16 файлов: `game_app.py`,
`build_apk.py`, PWA-скрипты и вспомогательные сценарии), проверки
`test_smoke.py`, `_meta_test.py`, `tests/_tools/verify_content.py`, а также
`README.md`, `ARCHITECTURE.md` и `pygbag.ini`.

- Перeчень всех файлов с числом строк и размером —
  `09_Исходный_код/_СПИСОК_ФАЙЛОВ.txt`.
- Запуск игры из папки с кодом: `py game.py` (нужны Python 3.12+ и
  `pygame-ce`).
- Проверки: `py test_smoke.py` (19), `py _meta_test.py` (12),
  `py tests/_tools/verify_content.py` (33). Последняя пишет отчёт в
  `docs/06_Тестирование/материалы/verify_report.json` относительно
  папки с кодом.
- Сумма строк 17 модулей совпадает с числами в документах: 7 656 строк.
- В комплект не включены двоичные материалы сборки: APK из
  `mobile/build` (391 МБ), `mobile/cdn_cache`, `mobile/intro_frames`,
  `mobile/sound`, `mobile/fonts` и рабочая копия `mobile/taran`
  (настоящий пакет — `taran/`). Это ассеты и артефакты, а не исходный код.

## Как открывать

- Документы — Microsoft Word, LibreOffice Writer или Google Docs.
  Для точной вёрстки лучше Word: шрифт Times New Roman, поля 2 см,
  интервал 1,5 и альбомные страницы с диаграммами.
- Оглавление — автоматическое поле TOC. Word обновляет его при открытии;
  если этого не произошло, выделите всё (`Ctrl+A`) и нажмите `F9`.
- Схемы — PNG для просмотра и `.drawio` для редактирования в draw.io
  (или в расширении Draw.io для VS Code). Файлы `.drawio` сохраняют
  отдельные блоки и подписи, а не являются картинкой.
- XLSX — пять листов: «Сводка», «Тест-кейсы», «Ошибки», «Среда», «Покрытие».
  Фильтры и ширины колонок уже настроены.

## Что проверено

- 64 автоматические проверки: 19 дымовых (`test_smoke.py`), 12 проверок
  мета-прогресса (`_meta_test.py`), 33 проверки контента
  (`docs/_tools/verify_content.py`). Все проходят.
- 30 тест-кейсов: 22 автоматических пройдены; 8 ручных, из них 1 пройден,
  6 не проведены и 1 заблокирован (BR-12).
- 12 дефектов: 11 закрыты, 1 открыт — targetSdk 33 при требовании Google Play 36.
- 11 реальных скриншотов и 8 схем, вставленных в документы.
- Оформление: A4, Times New Roman 14 pt, интервал 1,5, выравнивание по ширине,
  поля 2 см, титульные листы, нумерация страниц, подписи к таблицам и рисункам.

## Известные ограничения

- Отдельного главного меню нет: заставка сразу переходит в рейс.
- Отдельного экрана победы нет: победа показывается баннером, тостом и
  надписью «ДЕПО · ГОТОВО» в HUD. Поражение — итогом забега и новым забегом.
- Публикация в Google Play заблокирована: targetSdk 33 при требовании 36.
  Ручная установка APK работает.
- Проверка APK и PWA на живых устройствах, а также юзабилити-сессии
  не оформлены протоколами.
- Замер производительности (48,3 FPS, медиана 18,37 мс) выполнен в
  headless-режиме и не заменяет измерение на целевом устройстве.
- Название учебного заведения не указано: в исходных данных его нет,
  поэтому оно не придумывалось.

## Публикация на Google Drive (вручную)

Загрузка выполняется вручную: комплект не отправляется в облако
автоматически.

1. Войдите в Google Drive под своей учётной записью.
2. Создайте папку `Документация_Pygame_Серик_3-26п`.
3. Перетащите в неё **всю локальную папку** `Документация_Pygame_Серик_3-26п`
   целиком, а не отдельные файлы. Дождитесь завершения синхронизации.
4. Проверьте, что на Drive видны все 9 подпапок (включая `09_Исходный_код`),
   22 документа, папки `Материалы`, `Диаграммы`, `Скриншоты` и файл
   `09_Исходный_код/_СПИСОК_ФАЙЛОВ.txt`.
5. Откройте два-три документа в режиме просмотра. Если Google Docs
   перестраивает вёрстку, скачайте файл и откройте в Word — оригинал
   в DOCX остаётся неизменным.
6. Нажмите на папку правой кнопкой → «Поделиться». Для проверяющего
   достаточно ссылки «Все, у кого есть ссылка» с правом просмотра;
   для себя можно оставить доступ только владельцу.
7. Скопируйте ссылку и отправьте её вместе с комментарием: «Комплект
   документации, 21 DOCX + 1 XLSX, версия 3.2».
8. При обновлении комплекта загружайте новую версию папки поверх старой
   либо создайте папку с датой, чтобы не потерять предыдущую.

Не загружайте в эту папку `save.json`, готовые APK и служебные каталоги
`android_sdk/`, `mobile/build/`, `.apkbuild/`, `packages/`: в комплекте уже
лежит нужная часть исходного кода, а сборки и ассеты в него не входят.

## Пересборка комплекта

Из корня проекта `train_game_v3.0`:

```powershell
py -m pip install python-docx openpyxl pygame-ce
py docs_assignment/_build/build_all.py
py docs_assignment/_build/build_all.py --diagrams   # плюс пересборка схем
py docs_assignment/_build/validate_package.py        # проверка файлов
```

Скриншоты для комплекта лежат в `_docshots/` и копируются в пакет
автоматически. Драйвер съёмки — `_docshot.py`; он запускает игру в
headless-режиме и сохраняет кадры без ручного вмешательства.

Скрипты сборки находятся в `docs_assignment/_build/`:

| Файл | Назначение |
|---|---|
| `assign_docx.py` | оформление DOCX: стили, титул, TOC, таблицы, рисунки |
| `assign_data.py` | реальные данные, манифест, тест-кейсы, дефекты |
| `docs_01_04.py` | документы 01–04 |
| `docs_05_12.py` | документы 05–12: UML, блок-схемы, архитектура |
| `docs_13_14.py` | документы 13–14 |
| `docs_15_17.py` | документы 15 и 17 |
| `docs_18_22.py` | документы 18–22 |
| `build_xlsx.py` | книга `16_Тест-кейсы.xlsx` |
| `diagrams_build.py` | 8 схем PNG + `.drawio` |
| `build_all.py` | сборка всего комплекта |
| `validate_package.py` | проверка состава и оформления |
